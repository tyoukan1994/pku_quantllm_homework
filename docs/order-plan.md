# 价格触发下单方案（待确认，尚未实现）

课程要求在不确定时先提交方案。本文件只描述设计，不发送任何订单。

## 最小流程

```text
Tick 行情
  ↓
价格阈值判断（上穿/下穿，使用前一窗口数据）
  ↓
订单前检查
  ↓
构造 OrderRequest
  ↓
MainEngine.send_order(...)
  ↓
EVENT_ORDER / EVENT_TRADE 回报
```

拟采用限价单：当价格首次上穿用户明确输入的阈值时，只发送一笔、只开一手；同一合约
已有活动委托或持仓时不重复发送。方向、开平、价格、手数和合约必须在启动前明确显示。

## 必须具备的事前风控

1. **仿真限定**：仅允许经用户确认的 SimNow 环境，不支持真实账户；
2. **显式解锁**：默认 `dry-run`，只有输入一次性确认文字后才允许调用 `send_order`；
3. **合约白名单**：只允许本次交互选择的一个合约；
4. **限手限次**：单笔一手、每次运行最多一笔新委托；
5. **价格检查**：价格必须为正、符合最小变动价位，并限制与买一/卖一的偏离；
6. **去重与节流**：记录触发状态、活动委托和持仓，防止每个 Tick 重复发单；
7. **超时撤单**：订单超过限定时间未成交时撤单，不自动追价；
8. **紧急停止**：键盘中断后停止新委托并尝试撤销本程序产生的活动委托；
9. **完整回报**：打印并保存委托、成交、拒单和撤单结果，且日志脱敏。

## 验证顺序

1. 纯函数测试阈值穿越、重复触发和边界价格；
2. `dry-run` 打印拟发送的 `OrderRequest`，但不连接交易接口；
3. 连接 SimNow 后仍保持 `dry-run`，核对合约乘数和最小变动价位；
4. 用户再次明确确认账户、合约、方向、价格和一手数量；
5. 才进行一次受限的仿真委托，并核对订单与成交回报。

在老师或用户确认上述方案前，不实现第 4—5 步的自动发单。
