# 上交所 Level-2 历史回放与模拟交易原型

这批数据能够支持订单级挂单簿重建，以及基于历史行情的模拟下单和成交。当前已完成一个可操作的本地原型。

数据日期：2026-09-23。数据来源为老师提供的50只沪市股票 Level-2 行情，[下载课堂数据](https://github.com/aslan9/pku_quantllm/releases/tag/data-sse50-20260923)。原始文件只读，不重复上传；解压后保留三个 Parquet 文件名。

配套项目：[日内微观因子研究、结果与图表](research/README.md)。已对50只股票生成逐秒因子、1秒至5分钟的未来中间价目标，并按上午训练、下午前段验证、尾段留出测试。研究方法和边界见 `research/README.md`，原始汇总与样本也在该目录；研究页面只读，不推进模拟账户。

## 打开与操作

服务已启动时，打开 [本地模拟交易页面](http://127.0.0.1:8765)。

服务停止后，在终端运行：

```sh
cd lesson03/sse_l2_sim
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
export SSE_L2_DATA_DIR="/你的路径/sse50_20260923"
.venv/bin/python server.py --data-dir "$SSE_L2_DATA_DIR" --port 8765
```

也可以设置 `SSE_L2_DATA_DIR` 后运行本目录的 `run.command`，或把数据放入本目录的 `data/sse50_20260923/` 再双击启动。按 Control+C 停止服务。仅监听本机，不连接券商，也不发送实盘订单。

1. 选择证券代码，设置模拟初始资金和期初可卖持仓，点击“重置并从 09:30 开始”。切换股票需要重置，账户也随之重置。
2. 用“＋1 秒”“＋10 秒”“＋1 分钟”或指定时间推进行情。也可设置自动回放终点、选择 1／5／10／30／60 倍速度，点击“开始／继续自动回放”，从当前时刻连续播放。终点自动停止，支持暂停和继续；回放不能倒退，倒退需重置。
3. 模拟委托分为“限价单”和“市价单”两个面板，同时展示；买卖方向用按钮切换，数量共用。在对应面板填写价格并提交。市价单的四类指令通过按钮单击选择，并填写保护限价：买单为最高买价，卖单为最低卖价。各面板的“填入对手价”可填入当前对手方最优价。成交数量受重建盘口剩余量约束。
4. 以买一价提交买入委托，通常会进入排队状态。推进行情，观察前方挂单量变化及后续模拟成交；排队不保证成交。
5. 可撤销未完成委托，释放冻结资金或持仓。当日买入计入持仓，但不可当日卖出；要演示卖出，可以设置期初可卖持仓。
6. 自动播放时，十档盘口、累计市场成交量、最近 20 笔市场逐笔成交、账户和模拟成交记录同步更新。下单、撤单、手动跳转和重置会先暂停播放；页面隐藏时也自动暂停。已经提交给服务端的一次推进会完成，暂停后不再发起新的推进。

自动回放约每 250 毫秒更新一次页面，速度表示每秒真实时间推进多少秒历史时间，实际刷新率受本机性能影响。每次更新仍按顺序处理区间内全部逐笔事件，页面展示该区间结束时的盘口及最近成交，不保证每个中间盘口状态都单独显示。午休期间仍按钟表时间推进，不自动跳过。单一页面控制本地共享账户，多标签页同时推进会互相影响。

## 数据验证结果

完整重放 50 只股票的 10,066,831 条竞价事件：

| 检查 | 结果 |
|---|---:|
| 新增挂单事件 | 4,533,409 |
| 撤单事件 | 1,742,701 |
| 竞价成交事件 | 3,790,471 |
| 产品状态事件 | 250 |
| 撤单找不到原单 | 0 |
| 被动成交／集合竞价成交找不到挂单 | 0 |
| 数量扣减超过挂单剩余量 | 0 |
| 收盘竞价累计成交量与快照一致 | 50 / 50 只 |

每只股票在连续竞价快照中每隔 100 条抽取一条，共抽取 2,397 条。核对内容同时包含买卖各十档的价格、数量，以及累计成交量。

- 直接以快照标注时间为截止点，655 条完全匹配。
- 在快照标注时间所在的秒内寻找逐笔状态，2,396 条完全匹配。
- 增加对标注时间之前两秒的诊断搜索，2,397 条全部匹配。额外一条为 601166 的 11:25:11 快照，对应 11:25:10.990 的逐笔状态，相差 10 毫秒。匹配成功的其余样本所需向后搜索的最大偏移为 980 毫秒。

这表明快照时间和逐笔业务时间不能直接视为严格同步；不能凭快照标注时间把盘口变化提前给策略。上述时间搜索仅用于离线验证，模拟成交引擎按逐笔业务序号和逐笔时间向前处理，不使用未来快照。抽样匹配与成交量一致是重建可行性的证据，不等于已证明全部事件和所有时间点绝无缺失；只包含 50 只股票，因此频道内业务序号跳号也不能直接判定为丢包。

成交表另有 2,463 条 15:00 后的成交，当前竞价原型排除这些记录。2026 年规则已将盘后固定价格交易扩展到全部 A 股，后续应单独处理该交易阶段。

完整逐股结果见 `audit_results.csv` 和 `audit_results.json`。可运行 `.venv/bin/python audit.py` 重现。

## 字段解释与重建逻辑

没有供应商说明，以下映射结合数据关系、交易所历史接口定义和实际重建结果推断，尚未获得老师或供应商确认。

| 字段／取值 | 当前解释 | 验证情况 |
|---|---|---|
| `OrderKind=65/68/83` | ASCII `A/D/S`，新增／撤单／产品状态 | 与订单关系、交易时点相符 |
| 委托 `FunctionCode=66/83` | ASCII `B/S`，买／卖 | 全样本挂单扣减通过 |
| 状态 `FunctionCode=I/O/J/C/V` | 9:15、9:25、14:57、15:00、15:05 的阶段状态 | 依据出现时间推断，未用于触发模拟成交 |
| `OrderOriNo` | 原始订单编号，用于关联撤单和成交 | 所有撤单、被动成交均能关联 |
| `OrderNumber`、`BizIndex` | 消息编号／业务事件序号 | 回放使用 `BizIndex`；不把消息编号当原始订单编号 |
| 成交 `BidOrder/AskOrder` | 买／卖原始订单编号 | 与 `OrderOriNo` 关联 |
| 成交 `BSFlag=66/83/0` | 主动买／主动卖／方向未给出 | 方向为 0 的竞价成交按双边挂单扣减 |
| `Time` | `HHMMSSmmm` 的整型表示 | 样本具有毫秒位，但逐笔记录主要以 10ms 间隔编码；不是实际接收时间 |
| `Price` | 元，原始存储为 float32 | 归一到整数分，防止浮点数误差影响价位比较 |

核心区别：上交所逐笔新增委托中的数量可能是立即成交后的剩余挂单量。完全立即成交的主动订单可能没有新增委托记录；部分立即成交时，成交事件先出现，剩余挂单后出现。因此不能把所有成交量都从后出现的新增挂单量中再次扣减。

本原型直接重放剩余挂单簿：新增事件增加剩余挂单；撤单减少对应剩余量；成交减少当时已存在的挂单。不存在的主动方不虚造挂单，不存在的被动方记录为异常。同一股票竞价事件使用其频道内 `BizIndex` 顺序；当前已检查每只股票竞价事件属于单一频道，且业务序号唯一、时间不倒退。

从成交记录可以推断部分主动订单的成交数量，但完全立即成交订单的原始限价、市价类型、精确申报时间无法从这些字段唯一恢复。本原型不把推断信息伪装为原始报单。

## 已实现的规则与成交模型

按 2026-09-23 适用的《上海证券交易所交易规则（2026年修订）》实现连续竞价限价委托和市价委托的主要约束：

- 交易时段检查；按价格优先、时间优先扫描对手方挂单，使用对手方挂单价格模拟即时成交，支持部分成交。
- 价格最小单位为 0.01 元；普通主板股票假设涨跌幅为 10%，科创板为 20%；依据快照前收盘价计算并四舍五入。
- 主板买入为 100 股整数倍，单笔上限 100 万股；科创板最少 200 股、其后可按 1 股增加，限价单上限 10 万股、市价单上限 5 万股；可卖余额不足最小数量时允许全部卖出。
- 主板限价委托有效申报价格范围为基准价上下 2% 与十个最小价位的规定范围；科创板按其特别规定采用上下 2%。基准价依次取对手方最优价、本方最优价、最新成交价、前收盘价。该限价价格笼子不套用于市价单的保护限价。
- 资金／持仓冻结、撤单释放、成交更新；当日买入不可当日卖出。

四类市价指令按第 3.3.4—3.3.6 条实现，仅连续竞价可提交：

| 指令 | 即时成交与剩余量处理 |
|---|---|
| 最优五档即时成交剩余撤销 | 在对手方最优五个价位及保护限价范围内成交，剩余自动撤销 |
| 最优五档即时成交剩余转限价 | 先按五档成交；剩余按本单最新成交价转限价。无成交则取进入时本方最优价，无本方报价则撤销 |
| 本方最优价格 | 锁定进入时本方最优价，剩余量按此价排队；无本方报价则撤销 |
| 对手方最优价格 | 锁定进入时对手方最优价，不继续扫更差价位，剩余量按此价排队；无对手方报价则撤销 |

“五档”是五个不同价格，每档内可有多笔订单。实际成交及转限价均受保护限价约束；买入先按保护限价和完整数量检查资金，处理完成后仅冻结实际排队价格乘以未成交量。原型对最优报价或转限价价格超出保护限价的情况采用自动撤销，记录中明确标注“原型自动撤销”；这是保守处理约定，尚未通过真实交易主机回报验证该边界情况。

被动排队采用零市场冲击模型：提交时已有的同价挂单排在前面；撤单和历史成交推进队列，撤单本身不造成模拟成交。历史成交越过模拟限价、或到达排在其后的同价订单时，在对应历史成交数量范围内模拟成交。新发布的对手方剩余挂单若穿过模拟限价，也可在其剩余数量范围内成交。每只股票同时只允许一笔未完成的模拟委托，以避免多笔虚拟委托竞争同一历史成交量。

重复主动下单不能反复消耗同一份历史挂单容量；系统单独记录已被模拟交易使用的挂单容量。历史挂单簿本身保持独立，不因虚拟成交改变，避免后续真实撤单和成交无法重放。

## 当前边界

这是可验证的第一版历史模拟交易原型，尚非完整交易所仿真器。

- 模拟成交依赖“自己的订单不影响后续市场”的假设。加入自己的订单后，真实市场的成交路径、其他参与者反应均不可由单日历史数据确定；大额订单尤其不适合直接套用此模型。
- 支持连续竞价限价单和上述四类市价指令。集合竞价只回放历史结果；尚未实现虚拟订单参与集合竞价。14:57 起，未完成模拟订单标记为 `EXPIRED_AT_AUCTION_BOUNDARY`，这是原型边界，不是上交所对当日有效限价单的实际处理规则。
- 尚未实现盘后固定价格委托、停复牌和 IPO 特殊规则。缺少正式证券静态信息时，将 50 只股票按普通已上市主板／科创板处理；不能据此声称已覆盖全部特殊交易状态。
- 主板零股卖出目前采用保守限制：非整百数量必须等于全部可卖余额；未完整覆盖包含零股的所有合法组合。
- 零通信延迟，没有券商回报状态机；历史时间不等于行情到达账户的时间。尚未计入佣金、税费和滑点附加模型，成交明细中费用为 0。
- 页面为同一本地进程共享的单一账户；切换股票／重置会清空该模拟账户。未做多账户、跨日结算或多股票联合回放。卖出使用明确设置的期初库存，不代表数据自带真实持仓。

## 检查与文件

核心测试：`.venv/bin/python -m unittest -v test_engine.py`。

26 项核心测试已通过，覆盖四类市价指令、五个价格档而非五笔订单、双向保护限价、无报价撤销、转限价与冻结资金、科创板市价数量、流动性不可重复使用、后续成交，以及原有回放、限价、排队、T+1 等行为。14 项浏览器检查已通过，包括四类市价下单、科创板卖出、保护限价必填、自动回放准确停止、暂停继续、跨小时、下单及重置暂停；未发现 JavaScript 页面错误。结果见 `feature_checks.json`；`demo_trace.json` 是第一版限价功能的接口示例。

- `engine.py`：事件重放、挂单簿和模拟账户。
- `server.py`、`index.html`：本地服务和操作页面。
- `audit.py`、`audit_results.csv/json`：数据验证脚本及结果。
- `test_engine.py`：核心行为测试。
- `requirements.txt`：唯一第三方依赖 pyarrow。
