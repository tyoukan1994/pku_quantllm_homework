# A股策略平台

[第四讲完整报告](报告/第四讲回测报告.md) · [PDF报告](报告/第四讲回测报告.pdf) · [本次验收](验收说明-20261021.md)

通用的沪深A股日频回测平台。可创建策略、配置账户和股票池、运行回测、比较实验，也可在同一引擎上搜索参数和验证候选。平台不绑定任何单一策略或固定考核区间。

需求和模块边界见 `平台需求与架构.md`。已有课程量价研究作为历史实验保留，不再作为首页。

界面采用参数面板、绩效区及明细页签的工作台布局；设计参考及截图说明见 `界面设计说明.md`。精简代码包不包含本机行情、历史状态、用户工作目录或运行结果，仓库只提供报告与汇总表；完整实验记录须在有授权数据的本机重新生成。

## 立即使用

首次使用请先按下方命令创建虚拟环境并安装依赖；macOS 也可在安装后双击 **启动回测.command**。浏览器访问 `http://127.0.0.1:8501`，终端按 `Control+C` 停止。

界面入口：

| 入口 | 用途 |
|---|---|
| 回测 | 选择任意策略，设置参数、区间、资金、股票池和成交规则，运行并查看结果 |
| 策略库 | 查看模板、编写或导入Python策略、保存默认参数和版本 |
| 策略研究 | 对任意策略做参数搜索，或比较量价因子；训练完成后单独冻结候选并验证 |
| 实验记录 | 查看所有运行及失败原因，选择多个结果比较净值和指标，口径不同时提示 |
| 数据与规则 | 设置行情/历史状态目录、检查数据、查看撮合规则 |

默认进入待配置的回测页面，不自动加载任何历史策略成绩。标准配置与课程作业仅是可修改的预设；日期、10亿元资金及20日退出窗口都不是平台硬约束。

技术与文献策略可在“策略研究 → 策略探索”查看批量比较，在策略库中另存、修改或单独回测。新增RSI、布林带、突破、量价组合及公开文献因子，使用方法与数据边界见 `技术策略使用说明.md`；不替代原来的通用策略接口。

## 编写策略

将 `strategies/custom_template.py` 复制为自己的文件，定义继承 `Strategy` 的 `UserStrategy`。每个回测日收盘后调用一次 `on_close(context)`：

```python
from ashare import Strategy

class UserStrategy(Strategy):
    def on_close(self, context):
        universe = context.universe()
        if "000001.SZ" in universe:
            return {"000001.SZ": 0.5}
        return {}
```

| 返回值或接口 | 含义 |
| --- | --- |
| `{"000001.SZ": 0.5}` | 下一观测日开盘尝试调整到 50% 权重；未列出的已有股票目标为零 |
| `{}` | 下一观测日尝试清仓，停牌或跌停等仍可能卖不出 |
| `None` | 不下新订单，保留持仓；不自动恢复等权 |
| `context.date` | 当前收盘日 |
| `context.cash`、`context.equity` | 收盘现金与总权益 |
| `context.positions` | 持仓快照；研究模式是折算股数，严格模式是实际股数 |
| `context.universe()` | 截至当前有足够有效历史、最新价格/因子/成交额有效且未被已有状态排除的代码 |
| `context.history("close", 61, symbols, adjusted=True)` | 最多 61 行、截止当前日的复权价格，返回独立副本 |
| `context.history("amt", 20, symbols)` | 截至当前日的原始成交额；金额单位按配置换算 |

权重必须非负、有限，合计不超过 1，且不超过配置中的单只股票目标上限。剩余部分为现金目标。默认不做空、不融资。用户策略可以保存计数器等状态，每次运行重新创建策略实例。

历史接口不暴露未来行，也不使用最终日期因子来归一化历史绝对价格。策略代码是本机 Python 代码，并不是安全沙箱；自行读取整份源文件仍可能引入未来信息，应通过接口取数。不要执行不信任的策略代码。

## 成交与账户流程

每天依次处理公司行为及到账 → 执行前一日目标 → 收盘估值 → 记录权益 → 调用策略生成下一日目标。

1. 通用引擎默认首日为空仓；考核配置启用 `seed_previous_close`，以开始日前一交易日收盘形成信号，在首个考核交易日开盘建仓，首日损益和费用计入收益。启用 `liquidate_on_end` 后，最后 `liquidation_window` 个交易日只卖不买，每日开盘重试；默认窗口1，用户确认的执行修订窗口20。末日未能成交的持仓保留并报告失败，绝不强制按收盘价伪造成交。
2. 调仓时按当日开盘价格计算目标金额，先卖后买。目标包括被卖不出的原持仓；没有卖出的资产不会被当作现金再次使用。费用也占用预算，不允许负现金。
3. 当日买入的股份要等下一观测日才可卖出；交易日由文件日期轴提供，不使用自然日代替交易日。
4. 主板、创业板买入以 100 股整数倍申报；科创板至少 200 股，超过部分按 1 股递增。清仓可卖出全部可卖的整数零股。部分卖出按板块单位保守取整；没有模拟任意拼接零股的申报方式。
5. 开盘即涨停不买、开盘即跌停不卖，即使盘中打开也不补单。成交价格为开盘价叠加单边滑点，买入向上、卖出向下按 0.01 元取整。滑点后的价格超出日线价格范围或涨跌停边界时拒单。
6. 零成交额、缺失行情或因子、停牌、明确禁止方向的状态均不成交。使用当前全天数据进行事后有效性检查属于日线保守成交模型，不代表已证明开盘时有足够流动性。
7. 成交额上限为“上一观测日成交额 × amount_multiplier × participation_rate”，同股票当日买卖合计占用此上限。不开启用下一日全天成交额来提前筛选。单次股数上限按模拟限价申报保守限制：主板 100 万、创业板 30 万、科创板 10 万；默认大目标只部分执行；启用 `split_orders` 时按板块上限拆成子订单，子单共享当日容量并逐笔计费。
8. 未成交或部分成交的剩余委托当天失效；普通调仓不自动跨日重试，策略下一次返回权重时重新下单；预定退出窗口是例外，每日只卖不买地重试。研究模式按股票代码稳定排序依次买入，资金不足会影响后续股票的成交，订单表可审计。
9. 缺失持仓行情沿用最后有效估值并显示陈旧标记，不清零、不伪造成交。长时间缺失可能涉及退市；必须补充终止上市、清算价格和损失情景才能把这样的结果当作可信收益。

## 已实现的历史规则

| 项目 | 处理 |
| --- | --- |
| 普通主板涨跌幅 | 10% |
| 主板风险警示股票 | 有历史 ST 标记时，2026-07-06 前 5%，当日起 10% |
| 创业板 | 2020-08-24 前普通股票 10%、ST 5%；当日起通常 20% |
| 科创板 | 通常 20%，风险警示不改成主板的 5% |
| 除权除息参考价 | 优先显式涨跌停价；研究模式否则用 `前收盘 × 前日因子 / 当日因子` 按分取整，再算上下限 |
| 新股与特殊无涨跌幅日 | 优先逐日 `no_limit`；有真实上市日期且 IPO 在数据日期覆盖内时识别适用的新股前 5 日无涨跌幅；旧制度首日需发行价或明确涨跌停价 |
| 风险警示买入限制 | 有 ST 标记时，对单只股票当日累计买入量限制为 50 万股；不模拟个人适当性权限 |
| 印花税 | 仅卖出：2023-08-28 前 0.1%，之后 0.05% |
| 过户费 | 双向：2022-04-29 前 0.002%，之后 0.001% |
| 佣金、滑点 | 可配置假定参数，默认佣金 0.03%、每笔最低 5 元、单边滑点 5 基点 |

一般规则按日期计算，不能把最新规则整体套到 2020 年。用户可用 `stamp_tax_rate` / `transfer_fee_rate` 明确覆盖历史费率；本次作业统一采用题设卖出印花税万五，训练期也不改回旧费率。历史退市整理、重新上市、特殊复牌等应提供逐日精确限制覆盖默认推算。涨跌停价格取整和特殊参考价都应以交易所实际发布的数据为准。

## 两种账户口径，两个独立的严格开关

### 默认：复权研究模式 `accounting="research"`

`cumadj` 是乘法累计因子。买入 quantity 股时增加 `quantity / cumadj` 单位权益份额，持仓市值按 `份额 × 原始价格 × cumadj` 计算；卖出 quantity 股时减少相应权益份额。这样可跨分红、送转连续估值，避免把除权跳空当作市场亏损，也不会重复派发现金分红。

这相当于按数据商复权口径进行再投资近似，不是真实现金分红、税款、红股到账和实际股数账本。交易指令按整数股规则取整，但持仓折算股数可有小数；不足 1 股的残余权益默认留在持仓；本次考核显式启用 `write_off_research_dust`，在末日按零值核销为损失，不产生卖出成交或现金收入。整数股不得用此方式核销，受阻整数持仓仍保留。微小因子精度波动也可能产生少量折算残余。此模式适合目前只有价格和因子的教学研究。

### 严格账户模式 `accounting="strict"`

使用实际股数、现金及应收股息核算。持仓因子变化超过 `factor_tolerance`（默认 0.0001）且缺少对应公司行为时立即停止。阈值用于避免存储精度噪声，不能替代逐项公司行为核验。

支持普通现金分红、送转或缩股，以及现金到账日和新增股份可卖日期。含税股息按配置固定税率扣除，并先进入应收款，到账后才可买股票。无法仅根据因子辨认这些行为；配股认购、复杂重整、个税持有期补缴和退市清算不做自动猜测。产生不足一股或分笔缩股零股时停止并要求实际股数明细。

### 逐日交易状态开关 `strict_rules=true`

独立于账户模式。要求每次成交判断具有 `is_st`、`suspended`、`no_limit`，有限制日还要有精确 `limit_up`、`limit_down`，否则停止。

默认 `strict_rules=false` 可在没有精确涨跌停价时进行研究近似。本次已从本机授权 RQData 补充逐日 ST、停牌及上市日期；`require_st_history=true` 要求选股日和买入日均明确为非 ST，未知不买。它不等于 `strict_rules`：仍缺少全部特殊日的精确限价，不能宣称交易状态完全精确。不会把首次观测日期当作真实上市日期，也不会推断历史股票名称。

## 可选数据补充

把 `data_templates/` 中对应的空表头复制为以下文件，放在所选数据目录中。原始 Feather 不需转换。逐日状态不向前或向后填充，不把今天的 ST 标记套用到过去。

`market_state.csv`：`date,symbol,is_st,suspended,no_limit,limit_up,limit_down,can_buy,can_sell`。布尔值使用 true/false 或 1/0。`can_buy`、`can_sell` 可选；`no_limit=true` 的日期可不填涨跌停价格。

`instruments.csv`：`symbol,list_date,delist_date,issue_price`。上市日期必须是真实日期。退市日期只在到达该日后阻止成交，不会把未来将退市的股票从历史股票池提前剔除。即使有退市日期，仍需另外提供实际持仓处置/清算方案，不能默认按末价卖出。

`corporate_actions.csv`：`date,symbol,cash_per_share,share_multiplier,pay_date,share_available_date`。date 为除权除息日；每股派 0.246 元填 0.246，10 转 8 的 share_multiplier 填 1.8，不变填 1。pay_date 是现金实际到账日；share_available_date 是新增股份实际可卖日；均不能早于 date。同股同日行为应事先合并。因当前接口没有配股认购款等字段，不应用这张表假装处理复杂配股。

## 结果与验证

每次运行导出：

- `report.html`：独立 HTML 报告、净值图、费用后指标、模型假设、期末持仓和订单异常；无外部图表依赖。
- `equity.csv`：每日权益、现金、应收股息、仓位、净值、回撤、费用和陈旧估值数量。
- `trades.csv`：实际模拟成交，包含信号日、成交日、数量、价格和分项费用。
- `orders.csv`：全部下单尝试及拒单/部分成交原因。没有下单的目标差额不会伪造成交。
- `positions.csv`、`events.csv`：每日持仓和公司行为等事件。
- `summary.json`：指标、配置、策略参数、输入文件 SHA-256、文件时间/大小、版本信息和口径说明。
- `strategy.py`：本次实际运行的策略源码快照。

年化采用配置中的交易日数和实际收益期数；默认首日空仓时为观测日数减一，首日建仓时包含首日相对初始资金的收益，共使用全部观测日；夏普使用日收益样本标准差和配置的无风险年利率。换手为买卖成交额合计除以每日期初权益的累计值，属于双边换手。零波动时夏普为空，不伪造无穷值；没有回撤时 Calmar 为空。

可指定同数据池的单只股票作为参考，界面会标明不是市场指数。未提供指数数据时不伪造沪深300基准，也不输出所谓市场超额收益。参考股票收益用复权收盘净值，不含策略交易费用，因此是比较序列，不是同时模拟的同规则账户。

动量、均线等老示例仅验证系统流程。本次量价研究另有明确训练/验证/冻结考核记录，详见下节；单次短区间结果不证明因子稳定有效。保留按时间划分的验证区间；修改策略后应单独评估，不能用不断选择最好结果来替代验证。日线也不支持对盘中止盈止损顺序作精确判断。

项目结构：`ashare/` 为引擎、数据、规则、策略接口、报告与CLI；`ashare/platform/`为策略版本、统一运行、实验查询和训练/验证服务；`ashare/ui/`为五个独立页面；`strategies/`为内置模板；`tests/`为金融及平台回归验证；`app.py`仅负责启动。

## 通用策略研究

策略研究与单次回测都调用 `RunStore.run → cli.run_backtest → BacktestEngine`，不会维护第二套撮合逻辑。

1. 策略库中保存策略和默认参数，或直接选择内置模板。
2. 策略研究中选择“参数搜索”，输入参数网格，例如 `{"fast":[10,20],"slow":[60,120]}`；也可选择“量价因子比较”，勾选任意候选因子及持仓数量。
3. 自行设置训练日期、资金和费用，点击“运行训练搜索”。一次最多24个组合；此步骤不会自动运行验证区间。
4. 在研究记录查看所有训练候选及失败原因，选择一个候选，输入训练结束之后的验证区间。
5. “冻结并运行验证”先保存冻结文件，再用原始训练源码快照执行。冻结后不能换参数反复测试；失败时只能重试相同配置。训练与验证的数据版本及账户/成交配置必须一致，首日信号方式可不同。

自定义策略同样支持上述流程，不限于内置六种因子。“验证区间已在此前研究中查看”会写入记录；时间分离不自动等于新的盲测。

通过API调用平台服务：

```python
from pathlib import Path
from ashare import BacktestConfig
from ashare.platform import RunStore, StrategyStore, StudyStore

strategies = StrategyStore(Path("workspace/strategies"))
runs = RunStore(Path("runs"))
studies = StudyStore(Path("workspace/studies"), runs)
strategy = strategies.get("builtin:moving_average")
config = BacktestConfig(start="2020-01-02", end="2024-12-31")
study_id = studies.search(
    source="/path/to/feathers", metadata="/path/to/private_metadata",
    strategy=strategy, parameters=strategy.parameters,
    grid={"fast": [10, 20], "slow": [60, 120]}, config=config,
)
```

这只运行训练，不会隐式读取验证结果。数据、权限和成交假设由使用者提供。
