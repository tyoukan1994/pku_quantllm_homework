# 平台需求与架构

## 1. 两个目标

**回测平台**是可复用工具：用户能创建不同策略，独立配置数据、资金、日期、费用、股票池和撮合规则，保存及比较运行。

**寻找策略**是使用平台完成的研究任务：因子比较、参数搜索、训练候选筛选与后续验证都建立在同一套回测服务上。任何一个研究结果都不能反过来决定平台结构。

## 2. 功能边界

| 模块 | 必须做到 | 不承担 |
|---|---|---|
| 数据 | 加载日频行情、复权因子与可选历史状态；只读原始文件 | 用当前ST名单替代历史状态 |
| 策略库 | 多模板、自定义Python、导入、默认参数、版本保存 | 把某个选出的因子作为唯一策略 |
| 回测配置 | 任意可用区间、资金、费用、股票池、账户模式和退出方式 | 固定10亿元或固定2025—2026年 |
| 统一执行 | 使用同一引擎检查T+1、涨跌停、停牌、申报数量、容量与资金 | 在研究模块另写一套简化成交逻辑 |
| 实验记录 | 配置、参数、源码快照、输入哈希、净值、成交、订单、持仓、失败原因 | 覆盖旧结果或只保留最好一次 |
| 实验比较 | 多运行并列及净值图，检查区间、资金、成本、数据和引擎版本 | 给不同口径结果强行排名 |
| 策略研究 | 任意策略参数网格、量价因子候选、训练搜索、单独冻结并验证 | 自动反复试考核集或把已查看区间称作新盲测 |

## 3. 页面

1. **回测**：左侧为策略、参数、日期、初始资金及折叠的高级设置；右侧为指标、图表和明细页签。未运行时使用明确空状态，指标为“—”；运行后才显示实际结果。
2. **策略库**：模板或自定义策略、源码、默认参数；内置模板只能另存，自定义策略可保存新版本或用于回测。
3. **策略研究**：参数搜索或量价因子比较；训练设置可编辑，运行后单独选择候选、冻结和验证。
4. **实验记录**：旧版结果与新运行统一查询；可查看单个结果或多选比较。
5. **数据与规则**：数据路径、历史状态路径、数据检查和撮合规则。

界面没有口号、大幅宣传横幅、固定成绩展示或与操作无关的研究宣言；保留有意义的指标卡、功能面板、导航高亮、运行状态和图表层次。必要风险信息只出现在相关设置、比较差异及具体运行结果中。视觉设计参考及截图见 `界面设计说明.md`。

## 4. 调用关系

```text
app.py
  └─ ashare/ui/                         页面与交互
       ├─ backtest.py
       ├─ strategies.py
       ├─ research.py
       ├─ records.py
       ├─ data.py
       ├─ common.py                     配置表单与结果视图
       └─ design.py                     统一样式、导航和空状态
            ↓
     ashare/platform/                   不依赖Streamlit的应用服务
       ├─ StrategyStore                 策略版本与默认参数
       ├─ RunStore                      统一运行、保存、查询、比较
       └─ StudyStore                    候选搜索、冻结与验证
            ↓
     cli.run_backtest                   公共回测入口
            ↓
     DataBundle + Strategy + BacktestEngine
            ↓
     报告 / 净值 / 成交 / 订单 / 持仓 / 事件
```

数据检查页可直接调用DataBundle做只读检查；所有实际策略回测均通过RunStore和同一核心引擎执行。旧的固定课程脚本保留用于重现历史研究，不被新界面调用。

## 5. 保存结构

```text
strategies/                             内置模板，不能被策略库覆盖
workspace/
  settings.json                         本机数据连接设置
  strategies/<id>/
    metadata.json                       名称、默认参数、当前版本
    source-0001.py                      不覆盖的历史源码版本
    source-0002.py
  studies/<id>/
    strategy.py                         训练前固定的源码快照
    study.json                          网格、训练配置、所有候选及状态
    frozen.json                         选定候选、验证配置、冻结时间及查看标记
runs/<id>/
  request.json                          请求、参数、资金、股票池、来源与状态
  strategy.py                           本次运行源码
  summary.json                          指标、版本和输入指纹
  report.html
  equity.csv / trades.csv / orders.csv / positions.csv / events.csv
```

新运行均使用唯一ID。保存策略新版本不会改变旧运行或已训练候选的源码。元数据以原子替换写入，避免读取到半份记录。失败运行仍进入实验记录。

## 6. 研究约束

- 训练搜索最多24个组合，训练数据对象截断到训练结束日；不会自动启动验证。
- 验证开始必须晚于训练结束，账户和成交配置沿用训练设置，首日建仓开关可独立指定。
- 验证使用训练候选的原始源码及参数，先写冻结文件，再执行；数据或源码哈希改变时拒绝继续。
- 完成验证后不可在同一研究中换候选反复测试；失败只能重试原冻结配置。
- 验证区间是否曾被查看单独记录，不把时间分离误写成全新盲测。

## 7. 本次验收

- 新会话首页无任何策略收益或固定研究结果。
- 能从模板创建新策略，保存多版本，设置参数并运行。
- 能保存两次不同运行并比较，不覆盖历史结果。
- 能对自定义策略搜索多个参数组合，再单独冻结候选验证。
- 训练与验证共用统一入口；重叠日期、变动费用、篡改源码/数据和重复验证均有回归测试。
- 原有量价研究结果保留在实验记录中；此次框架重构没有重新挑选或修改其收益。
